# Design

## Context

See proposal.md - Why. 文档漂移集中在 PRD §7/§8 与 README 的完成度/状态描述；测试缺口集中在本轮其余变更新增的能力上。本变更不改变行为，故不设 spec delta。

## Goals / Non-Goals

**Goals:**

- 使 PRD / README 的完成度与里程碑状态与代码实际一致。
- 为新增能力补齐可回归的测试，`pytest` 全绿。

**Non-Goals:**

- 不修改任何生产代码行为。
- 不追求测试覆盖率指标本身，只补关键路径用例。

## Decisions

- **D1：以代码与提交为事实源对账文档。** 逐模块核对 §7 完成度表与 §8 里程碑标记，修正滞后项。
- **D2：测试跟随能力落点。** 各能力用例归入对应变更的任务；本变更负责跨变更的集成核对与最终全量回归。
- **D3：Docker 明确 Out of Scope。** 仅在文档标注接口保留状态，不实现。

## Risks / Trade-offs

- [文档再次漂移] → 在任务中约定"能力变更需同步更新 PRD/README"。
- [测试与实现节奏不同步] → 集成核对任务依赖相关变更完成，顺序执行。
